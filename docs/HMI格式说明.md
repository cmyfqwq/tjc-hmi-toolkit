# TJC / Nextion `.HMI` 工程文件格式说明

> 这份文档是**从文件结构反推**出来的（2026-09，实测于 TJC8048X270_011R + USART HMI 编辑器 1.68.1）。
> **官方没有公开这个格式的文档** —— 所以下面每一条都标了「实测」还是「推测」，别当权威手册用。

---

## 0. 一句话总览

```
.HMI = [魔数 4B] + [目录 28B × N] + [数据区]
数据区里每一项：main.HMI(页面索引) / N.pa(第 N 页) / Program.s(全局代码) / 资源区(字库·图片，占大头)
```

**★最关键的一条：这个容器没有校验和** ✓✓
把任意一个字节改掉、重新打包，上位机照样能打开 —— 这就是为什么**可以程序化生成整个工程**（本仓库工具链的基础）。

## 1. 容器层

### 1.1 目录项（28 字节）

| 偏移 | 长度 | 含义 |
|---|---|---|
| 0 | 16 | 文件名（`\0` 填充，ASCII） |
| 16 | 4 | **数据偏移**（小端 u32） |
| 20 | 4 | **数据长度**（小端 u32） |
| 24 | 4 | 标志（含义未完全弄清，实测见过 `220203264` / `768` / `167774464` / `6912`） |

### 1.2 ★★ 目录起点**不是固定值**（这是最容易踩的坑）

实测到至少三种：

| 文件来源 | 魔数（前 4~5 字节） | 目录起点 |
|---|---|---|
| 编辑器新建/生成的新格式 | `05 00 00 00` | **4** |
| 旧格式 | `1a 02 00 00 00` | **5** |
| 另一种（实测 `ui6.HMI`） | `17 00 00 00` | **4**，但**第一条目录项名字的首字节是 `0x00`** ✗ |

⇒ **写死任何一个起点都会静默读错** ✗：
- 按 `0x20` 读新格式 ⇒ **丢掉第一条 `main.HMI`** ✗（而且不报错，只是少一条）
- 按 `4` 读旧格式 ⇒ 整张目录错位 ✗
- 遇到"首条目名字首字节为 0"就 `continue` 跳过 ⇒ **整张目录错位** ✗

### 1.3 判据：用**连续性**自动定起点 ✓✓

目录项里带着**显式**的数据偏移 ⇒ 正常情况下：

```
前一项.off + 前一项.len  ==  后一项.off
```

把每个候选起点（4~40）都算一遍「连续率」，**挑最高的那个** ✓。
实测：起点错位时连续率掉到 **0**，正确时接近满分（本机三个样本：100% / 100% / 95.7%）✓

→ 实现见 [`hmi_container.py`](../hmi_container.py)（`detect_start()`）

## 2. 目录里有什么

| 条目 | 内容 |
|---|---|
| `main.HMI` | 页面索引（~112 B） |
| `N.pa` | **第 N 页**（导出成独立文件时扩展名是 `.page`） |
| `Program.s` | 全局代码（**明文**，GBK 注释 + `int sys0=0,sys1=0…` + `page 0`） |
| 若干「未命名」条目 | 注释 / 占位 |
| 资源区 | 字库、图片 —— **占文件体积的绝大部分**（本机样本 ~7.34 MB） |

> ★生成新工程时，**资源区可以整段复用**（`hmi_pack.py` 就是「保留原文件前段，只重写数据段」✓）

## 3. 页面层（`.pa` / `.page`）

```
页面文件 = [文件头] + [TLV 序列]
TLV      = [4B 总长][载荷]        总长 = 名字长度 + 值长度
载荷     = [明文属性名][值]        ★值的小端数值写在**载荷末尾**，前面补 0
```

**属性槽位长度是固定的**（实测）：

| 属性 | 槽位长 |
|---|---|
| `type` | 13 |
| `id` | 15 |
| `objname` | 14 |
| `x` `y` `w` `h` | 17 |
| `up` `down` `left` `right` | 12 |
| `bco` | 15 |

### 3.1 页面文件头（实测自洽的算法）

```
头部 = base(52B，抄一个空工程)
     + [4B 表长 = 4 + 8(N+1) = 12 + 8N]
     + [4B 页面块长度]
     + [(4B 控件偏移, 4B 控件长度) × N]
     + [4B 0, 4B 0 终止符]
```
- 第一个控件偏移 = **头部长度 + 页面块长度 + 4**（实测 36+701=737 ✓ 自洽）
- 头部 `@12` 的计数 = 控件数 N（实测编辑器 3 控件时写 3 ✓）
- 头部**前 4 字节是哈希，但编辑器不校验** ⇒ 沿用原值即可 ✓

## 4. 控件层

- **每个控件 = 一个 `att-N` 块**；`att-N` 之后的所有属性都属于它，直到下一个 `att-`
- **页面块是 `att-28`**
- ★**`total = 0` 是「页面块与控件块之间的分隔符」，不是文件结尾** ✗✓
  （第一版解析器就是因为把它当结尾，**漏掉了全部控件** ✗）

### 4.1 控件块编解码的三条铁律（往返测试逼出来的 ✓）

1. **写值必须沿用模板的「有效字节宽度」**（去掉前导零之后的长度），不能只写最小字节 ✗
   —— 例：`w=100` 模板写 2 字节 `64 00`；只写 1 字节 `64` 再左补零 ⇒ 会变成 `0x6400 = 25600` ✗
2. **事件块结构 = `[标记块] + [代码块]`**，代码块的**「名字」就是代码文本**；
   代码为空时那个块就是 `00 00 00 00`（total=0）—— **它同样要被消费掉** ✗，不能当成普通空块
3. **每条控件记录尾部还有 4 字节 `00 00 00 00`**；记录的「大小」= 全部块 + 这 4 字节

---

## 5. 事件代码

`codesdown-N` / `codesup-N` / `codesload-N` / `codesloadend-N` / `codesunload-N` / `codestimer-N`
是**无值标记块** ✓，**紧跟在它后面那个「名字就是代码文本」的块**才是代码 ✓。

实测读出来长这样：

```
page main
play 0,1,0
main.main.effect=0
```

## 7. 用这套工具能做什么（实测做过的事）

- 读出一个工程里**有哪些页、每页有哪些控件、控件名/坐标/文本**
- 读出**事件代码**（确认 `printh` 报文真的进了屏 ✓）
- **删掉一页**（`hmi_drop_page.py`，实测可用 ✓）
- **批量克隆控件**并改 `objname / x / y / w / h / txt`（`hmi_gen.py` ✓）
- **改控件属性 / 写事件代码**（`hmi_comp.py` ✓）
- **重新打包**成能直接被上位机打开的 `.HMI`（`hmi_pack.py` ✓）
- 工程自检（`verify_hmi.py`：容器连续率 / 页数 / 控件名逐条比对 / 事件代码 ✓）

**⇒ 全程不需要点那个上位机 GUI** ✓（这本来是这套工具存在的理由）
